# SIVAY API

Локальний Python 3.12/FastAPI сервіс для порівняння до п'яти культур на наступний сезон. Обсяг MVP: уся Україна, API без фронтенду. PostgreSQL підтримано; для локального запуску використовується SQLite без окремого сервера.

За відсутності агронома основний профіль `gaez_baseline` порівнює **умовний потенціал за реальними GAEZ** і повертає `LIMITED`. Сівозміна, строки посіву та погодні поправки не впливають на бал до затвердження правил. Кожен кандидат має `status=conditional` та пояснення обмежень. Це завершений технічний MVP для інтеграції, а не пройдена польова чи експертна валідація.

## Локальний запуск

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install -e . --no-deps
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Swagger: <http://127.0.0.1:8000/docs>. OpenAPI: `/openapi.json`. Конфіг читається з `.env` і змінних `SIVAY_*`; приклад — `.env.example`. За замовчуванням: `sqlite:///./sivay.db`, `rules/`, `data/gaez/manifest.json`, `data/regions.geojson`, `SIVAY_RANKING_PROFILE=gaez_baseline`.

Локальні растри й межі завантажуються окремим відтворюваним імпортером. Під час запиту рекомендації сервіс читає локальні дані. Без них повертає пояснюваний `ABSTAIN`. Завантаження даних у цій сесії дозволене користувачем у межах 10 ГБ.

```bash
.venv/bin/python scripts/import_mvp_data.py
```

Імпортер за замовчуванням обмежений 200 МіБ, бере 10 шарів SUX (HRLM, HP0120) для каталогу з офіційного лістингу FAO та національну межу України з geoBoundaries. Робочий набір займає близько 16 МБ. Походження, контрольні суми, ліцензії та консервативна дата доступності зберігаються разом із даними. SCX не використовується через непідтверджений код класу `10`; додаткове значення SUX `-1` явно маскується як відсутнє. Див. `docs/research-gaez.md`.

```bash
curl -s http://127.0.0.1:8000/v1/health
curl -s -X POST http://127.0.0.1:8000/v1/recommendations \
  -H 'Content-Type: application/json' --data-binary @examples/request.json
```

`examples/request.json` задає поле біля Полтави, ярі культури врожаю 2027 і дату 2026-10-21. Для іншого поля треба передати його власну геометрію. `as_of_date` — обов'язкова дата: використовуються лише дані, які були доступні до кінця цього дня UTC. Історичні приклади до дати завантаження можуть не мати доступних шарів через консервативне датування джерел.

Для синтетичної демонстрації всіх модулів без завантажень:

```bash
SIVAY_DEMO=true .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Усі синтетичні дані й правила явно позначено `demo`; вони відокремлені від реальних даних. `SIVAY_RANKING_PROFILE=validated` вмикає повний рушій, який потребує схвалених правил. З поточними чернетками він утримується від агрономічних рекомендацій. Відмінності консервативного алгоритму від суперечливих вимог початкового дизайну наведені в `docs/ranking-decisions.md`.

## Інтеграція з бекендом і фронтендом

| Endpoint | Поведінка |
|---|---|
| `POST /v1/recommendations` | Підготовка за потреби, ранжування, збереження результату |
| `POST /v1/recommendations?snapshot_id=...` | Відтворення збереженого snapshot з тим самим запитом |
| `GET /v1/recommendations/{id}` | Збережений результат |
| `POST /v1/fields/{field_id}/prepare` | Повний запит рекомендації; `202`, durable `job_id` |
| `GET /v1/jobs/{id}` | `queued/running/completed/partial/failed` |
| `GET /v1/catalog/crops?region=UA` | Каталог і статус перевірки культур |
| `GET /v1/rules/versions` | Версія та статус числових параметрів |
| `GET /v1/health` | БД, наявність даних і готовність профілів |
| `POST /v1/prices/import` | CSV `crop,price` у JSON з метаданими таблиці |
| `GET /v1/prices` | Остання імпортована таблиця з часом доступності |
| `PUT/GET /v1/fields/{id}/history` | Версійована історія культур |
| `PUT/GET /v1/fields/{id}/costs` | Витрати за культурами |
| `POST/GET /v1/fields/{id}/indices` | Приймання й читання готових NDVI/NDMI |
| `GET /api/fields/{id}/indices?index=NDVI&from=...&to=...` | Читання індексів у форматі адаптера платформи |

Для окремого браузерного фронтенду задайте його адресу в `SIVAY_CORS_ORIGINS`, наприклад `SIVAY_CORS_ORIGINS='["http://localhost:3000"]'`.

`POST recommendations` у MVP синхронно готує відсутній snapshot. Для попередньої асинхронної підготовки використовуйте `/prepare` та окремий worker:

```bash
.venv/bin/python -m app.worker
```

Черга зберігається в БД, задачі мають lease, токен власника й обмежені повторні спроби після втрати worker. Для одного циклу: `python -m app.worker --once`. PostgreSQL worker використовує `FOR UPDATE SKIP LOCKED`.

`examples/real-response.json` — фактична відповідь із завантаженими GAEZ для геометрії прикладу. Перевірено HTTP 200, п'ять кандидатів, `demo=false`, ідентичний replay, імпорт цін/витрат і виконання worker. Дані першого набору підтримують високий рівень технологій без зрошення (`high`/`none`); інші режими потребують відповідних шарів і за їх відсутності отримують `ABSTAIN`.

### Прості ціни та економіка

```bash
curl -s -X POST http://127.0.0.1:8000/v1/prices/import \
  -H 'Content-Type: application/json' --data-binary @examples/prices-import.json
```

Ціни у прикладі **вигадані для перевірки API**. Замініть CSV та метадані власними. Приймаються заголовки `crop,price` або `культура,ціна`, роздільник кома чи крапка з комою; культура — ідентифікатор з каталогу. Валюта, одиниця, дата публікації, ПДВ та основа поставки задаються один раз для таблиці. Для повного імпорту є `SIVAY_PRICES_PATH` із контрактом SPEC §3.1 і `SIVAY_EXCHANGE_RATES_PATH`.

Без фактичної чи явно наданої урожайності виручка й маржа залишаються `null`, ціни й витрати не переставляють культури. Урожайність GAEZ не підміняє фактичну. За відсутності затвердженої політики свіжості ціну можна показувати лише як довідкову з датою. Конвертація валют потребує курсу й `available_at`; bushel та непідтверджені товарні специфікації не вгадуються.

### Історія та витрати

Історія приймає мінімальні записи `[{"crop":"soybean","year":2025}]`; `season_year` також підтримано. Без метаданих надійність `low`. Повні записи відповідають SPEC. Можливі кілька культур за рік із різними `role`. Прямі дані в запиті мають пріоритет перед збереженою історією.

Витрати — об'єкт `crop_id -> {value, drying_per_t, logistics_per_t, includes}`: `value` у грн/га, додаткові статті у грн/т. `includes` указує вже враховані статті (`drying`, `logistics`). Автоматичних нормативів витрат немає: без джерела числові значення не вигадуються. `examples/costs.json` містить **синтетичний приклад**. Без урожайності витрати за тонну не перетворюються на загальну суму на гектар.

### Супутникові індекси та погода

Супутниковий API приймає `SatelliteSeries` із `index`, `sensor`, `native_resolution_m`, `processing_version`, `observations`. Кожне спостереження має `date`, `acquired_at`, `available_at`, `valid_pixel_fraction` і статистики. Сервіс перевіряє час доступності та якість, зберігає версії, віддає індекси й додає їх до snapshot. Завантаження Sentinel-2 та обчислення індексів із сирих каналів не входить у цей MVP. Фенологічні пороги не калібровані, тому супутник не змінює надійність історії чи рейтинг автоматично.

`SIVAY_SATELLITE_PATH` підтримує файл `{ "field_id": "...", "series": { ...SatelliteSeries... } }`. `SIVAY_WEATHER_PATH` — timestamped JSON із `latitude`, `longitude`, `records`; див. `docs/weather-provider.md`. Погодний адаптер має retry/cache й перевірку доступності прогнозів. У профілі baseline погода є довідковою; погодні штрафи вимкнені.

Власні API імпорту фіксують серверний час надходження. Завантажена сьогодні таблиця не стає відомою для вчорашнього snapshot навіть якщо її записи мають старі дати. Усі версії даних зберігаються; зміна джерел створює інший snapshot. Replay використовує вже зафіксовані дані, незалежно від поточного стану джерел.

## Перевірки та обмеження

```bash
.venv/bin/ruff check app tests
.venv/bin/python -m app.rules rules
.venv/bin/python -m pytest
```

CI включає PostgreSQL 16. Локальні SQLite-тести не є підтвердженням запуску PostgreSQL або Docker на цьому комп'ютері. Для PostgreSQL-тесту задайте окрему тестову БД через `SIVAY_TEST_POSTGRES_URL`. Тест створює й видаляє власну тимчасову схему.

`compose.yaml` містить API, worker та PostgreSQL. Для нього потрібні Docker і власний `POSTGRES_PASSWORD` у `.env`; запускайте `docker compose up --build`. Для відтворюваних агрономічних рішень потрібні джерела й експертне схвалення `rules/`, а також польова перевірка. Пакет для експертизи: `docs/agronomy-review.md`; технічний звіт: `docs/quality-report.md`.
