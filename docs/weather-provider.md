# Погодний адаптер MVP

Перевірено за офіційними джерелами 2026-10-21. Інтерфейс:
`WeatherProvider.get(kind, lat, lon, vars, period, as_of) -> list[WeatherRecord]`.
`period` — пара включених UTC-дат; `as_of` — дата (кінець UTC-доби) або datetime з часовою зоною.

## Джерела та ліцензія

Історія: `https://archive-api.open-meteo.com/v1/archive`, модель `era5_land`.
ERA5-Land має погодинні дані від 1950 року та затримку близько п'яти діб.
Фіксація моделі потрібна для зіставлення багаторічних рядів; режим best match не використовується.
Опади й ET₀ мають одиницю мм, вологість ґрунту — м³/м³, сніг — метри, температури — °C.
Відображення змінних та повні вимоги наведено в [Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api).

Короткий прогноз: `https://api.open-meteo.com/v1/forecast`, до 16 діб;
не всі моделі й змінні мають однакову глибину/горизонт. Див. [Forecast API](https://open-meteo.com/en/docs).
Адаптер не підміняє шари ґрунту іншої глибини. Відсутні колонки залишаються `None`.

Дані — CC BY 4.0 з атрибуцією Open-Meteo та вихідним джерелам. Free API дозволений лише
для некомерційного використання; комерційна платформа потребує відповідного плану.
Див. [умови сервісу](https://open-meteo.com/en/terms).

## Доступність і відтворення

Мережа вимкнена за замовчуванням. `OpenMeteoProvider(enabled=True)` — явний програмний
opt-in прототипу. Після timeout/transport error/429/5xx — максимум три спроби з backoff.
4xx, крім 429, не повторюються. Кеш зберігає точний запит з as_of у межах процесу;
повернуті записи копіюються. Застарілий кеш не підставляється автоматично.

Усі записи фільтруються за `available_at <= as_of`; прогноз додатково потребує
`issued_at <= available_at <= as_of`, `valid_time >= issued_at` і горизонту ≤16 діб.
Для нового HTTP-завантаження `available_at` дорівнює моменту отримання. Це консервативна
реальна доступність цього snapshot, а не вигадана дата першої публікації.
Новий реаналіз не можна завантажити сьогодні та представити як відомий у минулому:
якщо поточний час перевищує as_of, live-провайдер повертає порожній ряд.

Звичайний Forecast API не повертає надійний timestamp випуску моделі.
Параметр `forecast_issued_at` приймає лише timestamp, незалежно підтверджений клієнтом;
без нього прогноз не завантажується. Архівований прогноз імпортується з timestamped JSON.
Офіційний [Single Runs API](https://open-meteo.com/en/docs/single-runs-api) дозволяє вибрати
конкретний run, але час ініціалізації не дорівнює часу доступності; production-конектор
архіву випусків залишається окремою роботою. `generationtime_ms` не є issued_at.

## Локальний JSON і PREPARE

`FileWeatherProvider(path).records_for(lat, lon, as_of)` валідує точку й доступність.
`get(...)` додатково відбирає тип, змінні та період. Точка має збігатися з точкою поля
з точністю 1e-6°. Координати експорту — точка запиту, а не центр комірки провайдера.
`SIVAY_WEATHER_PATH` підключає цей файл у PREPARE; файл входить до request hash.
Формат: `{"latitude": 49.5, "longitude": 34.5, "records": [...]}`.
Кожен елемент records має обов'язкові `valid_time`, `available_at`, `kind`, `provider`, `values`;
прогноз має також `issued_at`. Дати включають часову зону.
`values` містить добові `tmin`, `tmax`, `precip`, `et0`, `soil_moisture_0_7`,
`soil_moisture_7_28`, `snow_depth`; невідомі значення — null.
Записи повинні бути добовими UTC; один provider має ідентифікувати конкретну модель,
версію та одиниці, наприклад `open-meteo:era5_land`.

## Ознаки та обмеження

`build_weather_features(records, as_of, parameters)` обчислює емпіричний midrank-перцентиль
вологості верхнього шару 0–7 см на останню доступну дату та 30-денної суми опадів.
Потрібні всі 30 порівнюваних річних зразків 1991–2020 з того самого provider і змінної;
для суми кожен день має бути присутній. Пропуски, лютий 29 без повного набору, інша модель,
недоступні на as_of кліматичні норми не заповнюються. Для січневих вікон можуть бути
потрібні дні 1990 року. Короткий прогноз не входить у поточну аномалію.
Для оперативного стану діє явний freshness limit 7 діб (параметр функції), який не є
агрономічним порогом. Поточний стан і кліматологія повинні мати однаковий часовий масштаб.
Норми обчислюються з наданих записів; автоматичне багаторічне завантаження не вмикається.

Класифікація dry/normal/wet_ok і множник можливі лише з `approved` параметрами, джерелом,
verified_by/verified_at та визначеними `weather_dry_percentile`/`weather_wet_percentile`.
Пороги повинні задовольняти `0 <= dry < wet <= 100`. Числа з дизайну не стають затвердженими
автоматично. Без схвалення перцентилі можна показувати, signal=unknown, multiplier=None.
Ризики FROST/WINTERKILL/HEAT/DRY_SPELL мають level=unknown: немає затверджених
порогів за культурою/регіоном. Це чесне обмеження MVP, що не додає погоді агрономічного впливу.
